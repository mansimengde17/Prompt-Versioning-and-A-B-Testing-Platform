Architecture

How a request moves through the system.

1
Prompt registry

Auto-incrementing versions with commit messages, unified diffs between any two versions, template variables validated at serve time, and one-call rollback.

2
Experiment engine

Variants with traffic percentages; assignment is a consistent hash of the user id, so the same user always sees the same variant.

3
Metric collectors

Latency, tokens, and cost built in; custom metrics like LLM-as-judge quality plug into the same async collection path.

4
Statistics

Welch's t-test per metric with p-values, confidence intervals, and minimum detectable effect at the current sample size.

5
Guardrails and audit

Experiments auto-stop on error-rate spikes; every creation, activation, winner declaration, and rollback lands in the audit log.

How to use

Runs fully offline with a deterministic provider; add API keys to switch to live models.

# offline: three variants, 600 requests, a winner
pip install -r requirements.txt
python demo.py
# -> v3 wins, p < 0.00001; promoted to active with audit trail

uvicorn src.promptlab.api:app --reload
curl -X POST localhost:8000/v1/completions \
  -d '{"prompt_id": 1, "variables": {"email": "..."}, "user_id": "u-42"}'
